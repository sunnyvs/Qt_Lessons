
# Как работает навигация в QML через StackView


Приложение на Qt Quick строится как дерево объектов. В самом верху — ApplicationWindow, это главное окно программы с рамкой, заголовком и кнопками управления от операционной системы. Всё, что мы пишем внутри этого окна, попадает в его центральную область и рисуется на экране.


```ApplicationWindow {
    id: window
    width: 640
    height: 480
    visible: true
    title: "Hello World"

    // всё, что здесь — попадает в центральную область окна
}
```


Окно — это контейнер самого верхнего уровня, его нельзя вложить в другой элемент, но внутри него может быть что угодно.


Для того чтобы приложение могло переключаться между разными экранами, внутрь главного окна кладут StackView. Это специальный контейнер, который работает как стопка страниц: он хранит несколько элементов, но показывает всегда только один — тот, что лежит сверху. Остальные скрыты, но существуют в памяти. StackView умеет добавлять страницы наверх, убирать их и анимировать переходы между ними.

```
StackView {
    id: stack
    anchors.fill: parent
    initialItem: mainPage
}
```


По сути, это механизм навигации внутри одного окна, без создания новых окон операционной системы.


Чтобы StackView знал, что показывать, ему передают компоненты. Компонент — это не сам объект, а его описание, шаблон, из которого StackView может создать экземпляр по требованию. Компоненты объявляются отдельными блоками и получают идентификаторы, по которым на них потом ссылаются.

```
Component {
    id: mainPage
    MainWindow { }
}

Component {
    id: reportPage
    ReportWindow { }
}
```
Пока эти страницы не понадобились, они не создаются — просто лежат как инструкции.


У StackView есть свойство initialItem, которое указывает, какую страницу показать при запуске приложения. Обычно это главная страница. StackView берёт соответствующий компонент, создаёт из него экземпляр, кладёт в стопку и показывает.


```
StackView {
    id: stack
    anchors.fill: parent
    initialItem: mainPage       // ← при старте покажет MainWindow
}
```
Сама страница — это обычный визуальный элемент, чаще всего Rectangle или Page, внутри которого размещены кнопки, поля, надписи и всё остальное содержимое.

```
// MainWindow.qml
Rectangle {
    id: root
    color: "#262626"

    RowLayout {
        anchors.centerIn: parent
        Button { text: "Докладная" }
        Button { text: "Служебка" }
    }
}
```
Страница ничего не знает о том, что она находится внутри StackView, не знает про другие страницы и не знает, как устроена навигация. Она просто рисует себя и реагирует на действия пользователя.


Когда пользователь нажимает кнопку, страница не может сама переключить экран, потому что не знает, куда переключать. Вместо этого она объявляет сигнал — специальное событие, которое она может испустить. Сигнал объявляется ключевым словом signal с именем.

```
Rectangle {
    id: root
    signal openReport()        // ← объявили событие

    Button {
        text: "Докладная"
        onClicked: root.openReport()   // ← испустили при клике
    }
}
```
Когда пользователь кликает по кнопке, обработчик нажатия вызывает этот сигнал, и страница как бы кричит наружу: «произошло событие openReport, кто слышит — реагируйте». При этом сама страница не знает, кто её услышит и что произойдёт дальше.


Реагирует на сигнал тот, кто создал эту страницу, — то есть главное окно. Когда Main.qml создаёт экземпляр MainWindow внутри компонента mainPage, оно может подписаться на его сигналы. Подписка оформляется обработчиком вида onOpenReport — то есть «приставка on плюс имя сигнала с большой буквы».


```
Component {
    id: mainPage
    MainWindow {
        onOpenReport: stack.push(reportPage)   // ← подписались на сигнал
    }
}
```
Внутри обработчика главное окно решает, что делать. В нашем случае оно вызывает stack.push(reportPage), что означает: «возьми компонент reportPage, создай из него экземпляр страницы отчёта и положи сверху стопки». StackView создаёт новую страницу, добавляет её в стек и проигрывает анимацию перехода. Пользователь видит, что экран как бы сменился.


На странице отчёта тоже есть кнопка «Назад». Она точно так же не управляет навигацией сама, а объявляет свой сигнал, например back, и испускает его при клике.


```
// ReportWindow.qml
Rectangle {
    id: root
    signal back()

    Button {
        text: "← Назад"
        onClicked: root.back()
    }
}
```
Главное окно ловит этот сигнал через onBack и вызывает stack.pop(), что означает «убери верхнюю страницу из стопки».

```
Component {
    id: reportPage
    ReportWindow {
        onBack: stack.pop()        // ← вернуться назад
    }
}
```
StackView удаляет страницу отчёта и показывает ту, что лежала под ней, — то есть снова главную. Переход анимируется в обратную сторону. Пользователь воспринимает это как возврат на предыдущий экран.


Таким образом, вся навигация управляется из одного места — из Main.qml. Страницы остаются «глупыми»: они не знают ни о других страницах, ни о том, что находятся в StackView. Они только объявляют сигналы и испускают их в нужный момент. Это делает их переиспользуемыми: одну и ту же страницу можно вставить в другое приложение и на те же сигналы повесить другие действия.


Важно не путать сигнал и обработчик. Сигнал объявляется внутри страницы и имеет имя, например openReport. Обработчик объявляется снаружи, там, где создаётся экземпляр страницы, и имеет имя onOpenReport — то есть к имени сигнала добавляется приставка on, а первая буква становится заглавной.

```
// Внутри страницы:
signal openReport()

// Снаружи, где создаётся страница:
MainWindow {
    onOpenReport: stack.push(reportPage)
}
```
Если сигнал называется back, обработчик — onBack. Регистр имеет значение: openReport и onOpenReport — разные вещи, и если написать что-то третье, QML не поймёт, о чём речь, и подчеркнёт строку как ошибку.



Ещё важно, что stack.push принимает не имя типа, а идентификатор компонента. ReportWindow — это тип, то есть имя файла ReportWindow.qml, из которого QML автоматически сделал компонент. А reportPage — это идентификатор конкретного блока Component, внутри которого лежит ReportWindow.
